# 夜ふかし時計25時 — PWA版

0時を過ぎても、今日の続き。Mac版・Windows版と同じ生活日付・25時記法を、ブラウザで使える時計・予定管理アプリです。インストール、ログイン、アカウントは不要です。

公開URL: https://crownecoyah.github.io/yofukashi-clock-25/pwa/

## 生活日付と25時記法

「X時まで今日」の境界は0〜12時、初期値は5時です。境界より前は前日の続き、境界ちょうどから当日になります。

| 実際の日時 | 境界5時での表示 |
| --- | --- |
| 2027/07/08 01:25 | 2027/07/07 25:25 |
| 2027/07/08 04:59 | 2027/07/07 28:59 |
| 2027/07/08 05:00 | 2027/07/08 05:00 |

曜日・予定の所属日は生活日付に従います。予定は開始実日時順に並び、境界設定に応じた生活日付でグループ化します。今日の予定は開始生活日付が今日のものです。「これからの予定」には進行中も含まれます。

## 主な機能・使い方

- 実時刻のアナログ時計、生活日付と25時デジタル時計。
- 秒表示、境界設定、デジタル時計のフォント3種・サイズ2種。
- 予定の追加・編集・削除、タイトル・メモ、開始と終了の生活日付。
- 00:00〜35:59で時刻入力。例：1月1日25:00〜28:00 → 実際の1月2日01:00〜04:00。
- 翌日終了は25時などで入力するか、終了日付を翌日に変更します。終了が開始以前なら保存できません。
- 「これから」「生活日付の今日」「すべて」の予定表示。
- 予定ごとの「カレンダーに追加」（ファイル共有／ダウンロード）と「ICSを保存」。全予定のICS書き出し。
- スマートフォン対応、基本的なオフライン操作。

時計のフォントはOS搭載フォントのみです。等幅（SFMono-Regular / Menlo / Consolas / monospace）、ゴシック（システムUI / Helvetica Neue / Arial / sans-serif）、明朝（Georgia / Times New Roman / serif）。フォントファイルの再配布や外部取得はありません。端末ごとに実際の書体は異なります。

## ホーム画面・デスクトップへの追加

HTTPSの公開URLを開きます。Chrome / Edgeの対応環境ではインストールボタン、アドレスバーまたはメニューを利用します。iPhone / iPadではSafariの共有メニューから「ホーム画面に追加」。対応するMacのSafariでは「ファイル」→「Dockに追加」。OS・ブラウザ・バージョンにより操作と対応が異なります。standalone起動中はインストール案内を隠します。

## 保存・プライバシー

予定はIndexedDB `yofukashi-clock-25-pwa`（DBバージョン1）の `events` に保存。設定はlocalStorage `yofukashi-pwa-settings-v1` に保存します。予定内容を外部サーバーへ送る処理、解析、広告、認証はありません。ICSの共有先はユーザー自身が選びます。

この端末・このブラウザ・このサイトの保存領域です。端末間／ブラウザ間の同期はありません。サイトデータ削除、ブラウザによるストレージ回収で失われる可能性があります。プライベートブラウズでは保存が維持されない場合があります。大切な予定は「全予定をICSで保存」からバックアップしてください。ICSをPWAへ再取り込みする機能はありません。

保存形式（1予定）:

```json
{
  "id": "UUID",
  "title": "深夜作業",
  "start": "2027-01-01T16:00:00.000Z",
  "end": "2027-01-01T19:00:00.000Z",
  "note": "メモ",
  "createdAt": "2026-09-16T00:00:00.000Z",
  "updatedAt": "2026-09-16T00:00:00.000Z",
  "timeZone": "Asia/Tokyo"
}
```

これは東京で生活日付2027/01/01、25:00〜28:00を入力した例です。`start` / `end` のUTC実日時を正とし、表示はその時点の端末タイムゾーン・境界から算出します。保存時のIANAタイムゾーン名も記録しますが、タイムゾーンを固定して表示する機能はありません。旅行や端末のタイムゾーン変更時には表示時刻が変わります。境界変更では実日時を動かしません。編集・削除はIndexedDBトランザクションで確定し、別タブによる同じ予定の変更は更新日時の照合で検出します。

## ICS・カレンダー追加

「カレンダーに追加」はICSファイルを作成して、対応するカレンダーに追加するための操作です。Web Share APIのファイル共有が可能なら共有画面、それ以外や共有失敗時にはダウンロードを使用します。共有をキャンセルした場合は勝手にダウンロードしません。「ICSを保存」なら常にダウンロードを選べます。端末によってはカレンダー画面が直接開かず、ファイル保存や共有画面になります。

Google Calendar API、EventKit、OAuth、APIキーを使用しません。ICSの追加は自動同期ではなく、PWAでの編集・削除は追加先へ連動しません。取り込み方法、同一UIDの更新・重複処理はカレンダーに依存します。

[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)に沿ってUTF-8、CRLF、TEXTの改行・カンマ・セミコロン・バックスラッシュのエスケープ、UTF-8文字を壊さない75オクテット以下の行折り返しを実装しています。VEVENTにはUID、DTSTAMP、DTSTART、DTEND、SUMMARY、メモがある場合DESCRIPTIONを含めます。UIDは保存したUUID由来で再書き出し時も同じです。

日時は独立モジュール `datetime.js` で生活日時から端末のローカル実日時に変換し、保存された実日時をICSのUTC（末尾Z）として出力します。固定UTC+9や25:00をICSへ渡しません。UTCにより、共有先にも同じ瞬間を渡せ、独自VTIMEZONE定義の不足を避けます。

日付の加減は暦の年月日を使い、1日を86,400,000msとして扱いません。夏時間で存在しない現地時刻はエラー。秋の重複時刻は先に来る時刻（初期値／Mac版相当）と後に来る時刻（Windows版相当）を予定入力内で選択できます。変換後の通常日時とUTCオフセットを保存前に表示します。地域の時間帯規則はOS・ブラウザのデータに依存します。

## オフラインと更新

初回はオンラインで読み込み、「オフラインの準備ができました」の表示を確認してください。以後は時計、生活日付、設定、予定CRUD、ICS作成をオフラインで利用できます。初回未読込の端末や、キャッシュ削除後のオフライン起動はできません。

`service-worker.js` はPWA内に限定し、HTML/CSS/JS/manifest/アイコン/ライセンスをバージョン付きキャッシュへ保存。外部CDN・Webフォント不要です。新バージョンは全PWAタブ・アプリを閉じた後に有効化し、自分のscopeに属する旧キャッシュだけを削除します。IndexedDB/localStorageは削除しません。アプリ資産の変更時には `VERSION` を更新してください。

- manifest: `./manifest.webmanifest`
- Service Worker: `./service-worker.js`
- start_url / manifest scope / SW登録scope: `./`
- 公開時scope: `https://crownecoyah.github.io/yofukashi-clock-25/pwa/`
- 通常アイコン192/512px、maskable 512px（既存画像を安全領域内へ縮小配置）、Apple touch 180px。

## 開発・GitHub Pages公開

リポジトリの `public/pwa/` が編集元、`docs/pwa/` が公開物です。既存サイトの公開方式は `main` ブランチの `/docs`。既存Mac / Windows紹介ページとは独立した静的HTML/CSS/ES Modulesで、追加の実行時ライブラリはありません。

Node.js 22.13以降:

```sh
node scripts/export-pwa.mjs
node scripts/serve-pwa.mjs
# http://localhost:4173/yofukashi-clock-25/pwa/
```

ファイルを直接開くfile://ではService WorkerやES Modulesを利用できません。HTTPSまたはlocalhostを使用します。

```sh
npm run test:pwa
npm test
# 既存紹介ページも含めた通常の再生成:
npm run build:pages
```

`build:pages` はPWAも `docs/pwa/` へコピーします。変更した編集元・公開物を両方コミットし `main` へpushすると既存GitHub Pagesで公開されます。Pages設定の変更は不要です。

## 対応範囲・制限

現行のSafari / Chrome / Edgeを想定しています。ES Modules、dialog、IndexedDB、Web Cryptoが必要。オフラインにはService Workerが必要です。Web Shareによるファイル共有の可否はブラウザごとに検出します。

ネイティブ版の常に最前面、Spaces、ログイン時自動起動、ウィンドウ復元、任意のインストール済みフォント列挙、EventKit直接登録はありません。通知・アラーム、認証、同期、繰り返し予定、終日予定、JSON復元は初期版対象外です。ブラウザが背面・スリープ中に時計処理を停止することがありますが、復帰時に端末時刻へ追従します。

検証した環境・未確認事項はリポジトリの `PWA-REPORT.md` を参照してください。モバイルの画面サイズ検証は実機検証と同義ではありません。

### 任意のブラウザ・保存テスト

Playwrightとfake-indexeddbはテスト専用で、サイトやPWAの依存には含めません。別ディレクトリにインストールした場合は、次の環境変数でモジュールの絶対パスを指定できます。

```sh
# 上記のローカルサーバーを起動した状態で実行
PWA_PLAYWRIGHT_MODULE=/path/to/qa/node_modules/playwright/index.mjs \
PWA_CHROME_PATH='/path/to/Chrome' \
node tests/pwa/browser-check.mjs

PWA_INDEXEDDB_MODULE=/path/to/qa/node_modules/fake-indexeddb/auto/index.mjs \
node --test tests/pwa/storage-check.mjs
```

ブラウザテストは一時ディレクトリの専用プロファイルに架空の予定を作成します。通常のブラウザの予定には触れません。`PWA_TEST_OUTPUT` でスクリーンショットと結果の保存先を指定できます。既定ではOSの一時ディレクトリを使用します。`PWA_TEST_URL` で検証対象を変更できます。公開先を指定した場合も入力内容をサーバーへ送る処理はありません。
